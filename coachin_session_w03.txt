Great, Grandeur. 👍 This is a solid controller example because it receives a route parameter and uses it to retrieve the appropriate category and its projects.

The key line is:

const categoryId = req.params.id;

Here, req.params.id gets the id value from the URL and stores it in categoryId. Your controller then uses that same value in both model functions:

getCategoryById(categoryId);
getProjectsByCategoryId(categoryId);

So the controller acts as the middleman between the route, the models, and the view.

Topic 4: Error Handling

Please paste the error-handling code from your project, such as your 404 or 500 middleware/page.

app.use((err, req, res, next) => {
    // Log error details for debugging
    console.error('Error occurred:', err.message);
    console.error('Stack trace:', err.stack);

    // Determine status and template
    const status = err.status || 500;
    const template = status === 404 ? '404' : '500';

    // Prepare data for the template
    const context = {
        title: status === 404 ? 'Page Not Found' : 'Server Error',
        error: err.message,
        stack: err.stack
    };

    // Render the appropriate error template
    res.status(status).render(`errors/${template}`, context);
});

It is useful for your application to show a 404 page for a missing page instead of simply showing the user the raw error or a blank page so that the user will know that what he is trying to access is not available or what he enters is not on the website

Exactly, Grandeur. 👍 That's the main purpose of a user-friendly 404 page: instead of leaving the user confused by a technical error, you clearly communicate that the requested resource couldn't be found.
