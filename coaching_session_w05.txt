const requireRole = (role) => {
    return (req, res, next) => {
        // Check if user is logged in first
        if (!req.session || !req.session.user) {
            req.flash('error', 'You must be logged in to access this page.');
            return res.redirect('/login');
        }

        // Check if user's role matches the required role
        if (req.session.user.role_name !== role) {
            req.flash('error', 'You do not have permission to access this page.');
            return res.redirect('/dashboard');
        }

        // User has required role, continue
        next();
    };

 };















Well done, Grandeur! 😊 You've now shown both requireLogin and requireRole. Let's examine how they work together.
Understanding your requireRole middleware
Your function accepts a role, such as 'admin', and returns middleware that checks whether the logged-in user has that role.
There are three important steps:
1. Check authentication: If the session or user information is missing, the visitor is redirected to /login.
2. Check authorization: If req.session.user.role_name does not match the required role, the visitor receives a permission error and is redirected to /dashboard.
3. Allow access: If the user's role matches, next() allows the request to continue.
For example, a route might use:
router.get("/admin", requireRole("admin"), showAdminDashboard);


This protects the administrator route even if someone types /admin directly into their browser.
The difference between your two middleware functions
- requireLogin asks: Is this user logged in?
- requireRole('admin') asks: Is this user logged in and authorized as an administrator?
Both checks are important because authentication does not automatically grant permission to access every part of your application.
Grandeur, why should your application check req.session.user.role_name on the server instead of trusting a role value submitted by the user through a form?

The application should check req.session.user.role_name on the server instead of trusting a role value submitted by the user through a form so that there will be no bypass to happen and that the flow of the program will be smooth
Great explanation, Grandeur! 😊 You're thinking about security in the right way.

You're correct that checking req.session.user.role_name on the server helps prevent users from bypassing role restrictions.

Here's why this matters:

Form data can be manipulated. A user might change a submitted role value from user to admin.

The server must make the authorization decision. Your middleware checks the role stored in the session instead of trusting a value supplied by the browser.

Unauthorized access is blocked. If the role doesn't match the required role, your middleware redirects the user rather than calling next().

One additional consideration: the session itself must be established securely, and users should not be allowed to modify their own role through an unprotected registration or profile form.
